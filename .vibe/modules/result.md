# Module: result

**Role:** Runs the detection pipeline and provides the render primitives for its outcome: hides/clears any previous result, renders the reconstructed image, its detected grid size, an interactive color palette, JSON and GIF download links, and a pixel-art confidence verdict.
**Files:** `src/result.ts`
**Exports:** `resetResult(elements: ResultElements): void`, `renderPalette(container: HTMLElement, palette: readonly SerializedPaletteColor[], activeIndex: number | null, callbacks: PaletteCallbacks, mergeSelection?: ReadonlySet<number>): void`, `renderReconstruction(canvas: HTMLCanvasElement, serialization: PixelArtSerialization): void`, `renderGridSize(element: HTMLElement, serialization: PixelArtSerialization): void`, `renderDownloadLink(link: HTMLAnchorElement, serialization: PixelArtSerialization, sourceFileName: string | undefined): void`, `toJsonFilename(sourceFileName: string | undefined): string`, `renderGifDownloadLink(link: HTMLAnchorElement, note: HTMLElement, serialization: PixelArtSerialization, sourceFileName: string | undefined): void`, `toGifFilename(sourceFileName: string | undefined): string`, `renderConfidence(element: HTMLElement, confidence: ConfidenceResult): void`, `computeDetection(image: HTMLImageElement): DetectionResult`, `computeManualDetection(image: HTMLImageElement, crop: CropRect, gridWidth: number, gridHeight: number): DetectionResult`, types `ResultElements`, `PaletteCallbacks`, `DetectionResult`
**Depends on:** `modules/grid-detection.md`, `modules/palette-extraction.md`, `modules/serializer.md`, `modules/image-crop.md`, `modules/gif-encoder.md`

`resetResult`, `renderPalette`, `renderDownloadLink`, `toJsonFilename`, `renderGifDownloadLink`, `toGifFilename`, `renderGridSize`, and `renderConfidence` have no canvas/image-decode dependency and are covered by automated tests. `renderReconstruction` (draws to a live `<canvas>`, see `.vibe/decisions/007-reconstruction-rendered-to-live-canvas.md`) and `computeDetection` (the pipeline: `pixel-data` → `grid-detection` → `palette-extraction` → `serializer`/`confidence`) depend on real canvas/image-decode behavior jsdom doesn't provide, so they're verified in a real browser instead — same precedent as `pixel-data.ts` (`.vibe/decisions/003-canvas-pixel-extraction-verified-at-runtime.md`). `computeManualDetection` runs the same pipeline on a user-confirmed crop and grid size instead of automatic detection (`gridRegularity` fixed at 1, a factual statement rather than a quality judgment) — see `.vibe/decisions/020-manual-grid-adjustment-as-crop.md` — and shares `computeDetection`'s canvas dependency, so it's verified the same way. `renderReconstruction` looks up each pixel's color by its palette `index`, not its array position, since `modules/palette-editor.md`'s removal can leave gaps. `renderGridSize` writes the serialization's `gridWidth × gridHeight` as a plain sentence, unconditionally — it reflects whatever the pipeline actually detected regardless of the confidence verdict, since it's a factual reading of the detection rather than a judgment of its quality. `renderPalette` builds one interactive swatch per color: a click on its color box calls `onSelect`; every entry except the reserved transparent one (index 0) also gets a color input (`onModify`) and a remove button (`onRemove`); the active entry is visually highlighted. Passing an optional merge-selection set switches every non-transparent swatch into a checkbox (`onToggleMerge`) instead, and adds a "merge into this color" action (`onMergeInto`) on any swatch that's both selected and part of a selection of two or more — see `modules/reconstruction-editor.md` and `.vibe/decisions/013-palette-merge-as-distinct-selection-mode.md`. Both download links are built as `data:` URLs rather than `Blob` object URLs specifically so they stay testable — see `.vibe/decisions/008-json-download-via-data-url.md`. `renderGifDownloadLink` delegates the actual encoding to `modules/gif-encoder.md`'s `encodeGif`: when the current palette exceeds GIF's color limit it leaves the link visible but disabled (`aria-disabled`, no `href`/`download`) with a plain-word note, and otherwise sets the link normally and, only when `encodeGif` reports a flattened color, fills the same note element with a non-blocking explanation — see `.vibe/decisions/023-gif-export-flattens-non-reserved-alpha.md`. The confidence verdict is written into a `role="status"` element so it's announced to assistive tech the same way the rest of a newly-produced result is; computing it from the pipeline's grid/palette and rendering it is now the caller's responsibility (`app`), not this module's.
