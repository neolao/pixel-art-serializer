# Module: result

**Role:** Runs the detection pipeline and provides the render primitives for its outcome: hides/clears any previous result, renders the reconstructed image, its detected grid size, an interactive color palette, a JSON download link, and a pixel-art confidence verdict.
**Files:** `src/result.ts`
**Exports:** `resetResult(elements: ResultElements): void`, `renderPalette(container: HTMLElement, palette: readonly SerializedPaletteColor[], activeIndex: number | null, callbacks: PaletteCallbacks, mergeSelection?: ReadonlySet<number>): void`, `renderReconstruction(canvas: HTMLCanvasElement, serialization: PixelArtSerialization): void`, `renderGridSize(element: HTMLElement, serialization: PixelArtSerialization): void`, `renderDownloadLink(link: HTMLAnchorElement, serialization: PixelArtSerialization, sourceFileName: string | undefined): void`, `toJsonFilename(sourceFileName: string | undefined): string`, `renderConfidence(element: HTMLElement, confidence: ConfidenceResult): void`, `computeDetection(image: HTMLImageElement): DetectionResult`, types `ResultElements`, `PaletteCallbacks`, `DetectionResult`
**Depends on:** `modules/grid-detection.md`, `modules/palette-extraction.md`, `modules/serializer.md`

`resetResult`, `renderPalette`, `renderDownloadLink`, `toJsonFilename`, `renderGridSize`, and `renderConfidence` have no canvas/image-decode dependency and are covered by automated tests. `renderReconstruction` (draws to a live `<canvas>`, see `.vibe/decisions/007-reconstruction-rendered-to-live-canvas.md`) and `computeDetection` (the pipeline: `pixel-data` → `grid-detection` → `palette-extraction` → `serializer`/`confidence`) depend on real canvas/image-decode behavior jsdom doesn't provide, so they're verified in a real browser instead — same precedent as `pixel-data.ts` (`.vibe/decisions/003-canvas-pixel-extraction-verified-at-runtime.md`). `renderReconstruction` looks up each pixel's color by its palette `index`, not its array position, since `modules/palette-editor.md`'s removal can leave gaps. `renderGridSize` writes the serialization's `gridWidth × gridHeight` as a plain sentence, unconditionally — it reflects whatever the pipeline actually detected regardless of the confidence verdict, since it's a factual reading of the detection rather than a judgment of its quality. `renderPalette` builds one interactive swatch per color: a click on its color box calls `onSelect`; every entry except the reserved transparent one (index 0) also gets a color input (`onModify`) and a remove button (`onRemove`); the active entry is visually highlighted. Passing an optional merge-selection set switches every non-transparent swatch into a checkbox (`onToggleMerge`) instead, and adds a "merge into this color" action (`onMergeInto`) on any swatch that's both selected and part of a selection of two or more — see `modules/reconstruction-editor.md` and `.vibe/decisions/013-palette-merge-as-distinct-selection-mode.md`. The download link is built as a `data:` URL rather than a `Blob` object URL specifically so it stays testable — see `.vibe/decisions/008-json-download-via-data-url.md`. The confidence verdict is written into a `role="status"` element so it's announced to assistive tech the same way the rest of a newly-produced result is; computing it from the pipeline's grid/palette and rendering it is now the caller's responsibility (`app`), not this module's.
